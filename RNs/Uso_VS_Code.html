  • Site oficial do Visual Studio Code;
  • VS Code for Windows.
  • Downloads do VS Code (mutiplataforma: Windows, Linux, macOS).

Extensões Recomendadas

Elas podem ser baixadas à partir do Visual Studio Marketplace:

Observações:

  1. A extensão Python da Microsoft já instala/integra Pylance como dependência opcional, portanto você não precisa ficar procurando configurações alternativas de language server. (Visual Studio Marketplace)
  2. Existe a extensão Markdown Preview Enhanced: que permite trabalhar com Markdown + MathJax/KaTeX, Mermaid, PlantUML, Pandoc, PDF etc. Apesar de ser uma extensão ppoderosa e conhecida, ela tenta resolver muita coisa sozinha (fonte de instabilidades no VS Code).
  3. Existe a extensão Arduino Community Edition, é um fork comunitário da antiga extensão da Microsoft, mas não se recomenda sua intalação conjunta com a extensão PlatformIO.
  4. Evite instalar muitas extensões: muitas extensões → mais processos → mais consumo → mais possibilidade de conflito → eventualmente alguma deixa de funcionar (exigindo o re-inicio de todo o VS Code).
  5. Para minimizar a execução simultânea de várias extensões, você pode criar perfis no VS Code. Por exemplo: poderiam ser criados 3 perfis: Python, Embedded e Markdown/Documentação. Você pode ter PlatformIO habilitado no perfil Embedded, mas não necessariamente carregado quando estiver trabalhando em Python/Markdown.

Executar progressivamente scripts Python

Você pode usar o .py normal, mas colocar:

# %%

para separar blocos.

Por exemplo:

# %%
import numpy as np
import matplotlib.pyplot as plt


# %%
R = 10e3
C = 100e-6
tau = R*C


# %%
t = np.linspace(0, 5, 500)
vc = 1 - np.exp(-t/tau)


plt.plot(t, vc)
plt.grid()
plt.show()

O VS Code passa a mostrar Run Cell em cada bloco # %%.

Ou seja, você consegue fazer:

xxxxxxxxxx
        arquivo .py normal
               │
               ├── executar tudo
               │
               ├── executar apenas # %%
               │
               ├── depurar
               │
               ├── usar terminal
               │
               └── visualizar gráficos

sem ncessidade de usar Jupyter/Notebook organizando os comandos dentro de um arquivo .ipynb.

Transformar .py → .ipynb

Vantagem adicional: se você quiser, pode posteriormente transformar um coódigo Python .py com linhas # %% em um notebook .ipynb, mas para tanto é necessário ter a extensão Jupyter instalada.

Neste caso, no exemplo do programa acima, usar:

Command Palette (⇧⌘P) → Jupyter: Export Current Python File as Jupyter Notebook

e o VS Code cria o .ipynb.

Assim você obtêm:

xxxxxxxxxx
controle_rc.py
controle_rc.ipynb

com cada bloco delimitado por # %% transformado em uma célula.

Transformar .ipynb → .py

Um .ipynb aberto no VS Code pode ser exportado para:

xxxxxxxxxx
.py

Pode-se trabalhar assim:

xxxxxxxxxx
                 ┌──────────────┐
                 │  programa.py │
                 │   # %%       │
                 └──────┬───────┘
                        │
                     exportar
                        |
                        ↓
                 ┌────────────────┐
                 │ programa.ipynb │
                 └────────────────┘

Eventualmente para:

  • desenvolver inicialmente tudo em .py;
  • usar # %% para dividir blocos de programação;
  • executar células individualmente quando estiver explorando;
  • manter o código sob controle de versão;
  • quando quiser entregar uma demonstração (notebook), exportar para .ipynb;
  • acrescentar textos explicativos em Markdown no notebook.

Perfis/Profiles no VS Code

Para minimizar a execução simultânea de várias extensões, você pode criar perfis no VS Code. Por exemplo: poderiam ser criados 3 perfis: Python, Embedded e Markdown/Documentação. Algo como:

Deixaria Git, terminal, editor, Explorer etc. como recursos comuns do VS Code.

A idéia é evitar instalar tudo no Default Profile e deixar o VS Code algo pesado e instável (em relação às extensões), seguindo recomendação da prípria Microsoft.

Para criar os Perfis

Code → Settings → Profiles → Profiles

ou usar:

⇧⌘P

e procurar:

xxxxxxxxxx
Profiles: Create Profile

A versão atual do VS Code possui um Profiles Editor específico para criar, modificar, importar/exportar e administrar os perfis.

Outra maneira é clicar no ícone de Manage (engrenagem) na barra lateral e escolher o gerenciamento de Profiles.

Criando Perfil Python

Recomendado começar com um perfil vazio.

Escolha:

Create Profile → Empty Profile

Nome:

xxxxxxxxxx
Python & Jupyter

Escolha um ícone qualquer — por exemplo 🐍, se disponível.

O ponto importante é não copiar seu Default Profile inteiro, porque queremos justamente reduzir a quantidade de extensões ativas.

O VS Code permite criar um Empty Profile que começa sem suas extensões, configurações, snippets etc.

Instale somente:

xxxxxxxxxx
ms-python.python
ms-python.vscode-pylance
ms-python.debugpy
ms-toolsai.jupyter

Ou, pela interface:

⇧⌘X → Extensions

procure:

xxxxxxxxxx
Python
Pylance
Python Debugger
Jupyter

Essas quatro são suficientes para trabalhos com Python.

Configurando o Conda

Por exemplo, suponha 2 ambientes/environments Python:

xxxxxxxxxx
controle

e:

xxxxxxxxxx
robotica

Você pode abrir um projeto e usar:

⇧⌘P → Python: Select Interpreter

e selecionar:

xxxxxxxxxx
Python (controle)

ou:

xxxxxxxxxx
Python (robotica)

O importante é que o environment Conda não precisa ser um Profile diferente.

Distinção que vale muito a pena manter:

xxxxxxxxxx
PROFILE
   ↓
define ferramentas do VS Code




CONDA ENVIRONMENT
   ↓
define bibliotecas/runtime Python

Portanto:

xxxxxxxxxx
Python & Jupyter
       │
       ├── Conda: controle
       ├── Conda: DSP
       ├── Conda: robotica
       └── Conda: ML

Você não precisa criar um Profile para cada environment.

Obs.: um perfil não contém seus environments Conda, por exemplo.

Portanto:

xxxxxxxxxx
Python-Jupyter.code-profile
       ↓
extensões + configurações do VS Code




controle.yml
       ↓
bibliotecas do Conda

São coisas diferentes.

Isso pode faciliar exportar environments Conda.

Você poderia ter, por exemplo:

xxxxxxxxxx
MeuAmbiente/
│
├── vscode/
│   └── Python-Jupyter.code-profile
│
├── conda/
│   └── controle.yml
│
└── projetos/
    └── ...

e transportar separadamente a configuração do editor e o ambiente Python.

Detalhe do PlatformIO

O PlatformIO traz uma quantidade razoável de funcionalidade própria:

  • CMake;
  • Makefile Tools;
  • Arduino;
  • ESP-IDF;
  • vários debuggers;
  • extensões para cada placa.

Exportanto Perfis

Depois que você montar os três perfis e verificar que estão funcionando, exportaria cada um deles.

Fazer:

⇧⌘P → Profiles: Export Profile

o VS Code gera um arquivo como:

xxxxxxxxxx
Python-Jupyter.code-profile

Esse é o arquivo que você pode guardar como backup ou levar para outro computador.

E não, não é XML.

É um arquivo de configuração baseado em JSON.

O VS Code permite exportar um Profile para um arquivo .code-profile e depois importá-lo em outra máquina. Mas para tanto, recomenda-se cirar uma pasta própria para os mesmos, por exemplo:

xxxxxxxxxx
~/Documents/VSCode-Profiles/

e colocar lá dentro os diferentes perfis:

xxxxxxxxxx
~/Documents/VSCode-Profiles/
├── Python-Jupyter.code-profile
├── Markdown-Docs.code-profile
└── ESP32-Arduino.code-profile

Isso é particularmente interessante porque você pode posteriormente configurar o mesmo ambiente num Ubuntu ou outro PC.

E existe ainda uma opção bastante prática: pela linha de comando do VS Code você pode abrir uma pasta já especificando o Profile:

xxxxxxxxxx
code ~/Projetos/Python/Controle --profile "Python & Jupyter"

O CLI oficial suporta tanto --profile quanto instalação/listagem de extensões por Profile.

Mas não confuda profiles com arquivos de um projeto. Se recomenda deixa-los separados:

xxxxxxxxxx
~/Projetos/
    Python/
    DSP/
    Controle/
    ESP32/

e:

xxxxxxxxxx
~/Documents/VSCode-Profiles/
    Python-Jupyter.code-profile
    Markdown-Docs.code-profile
    ESP32-Arduino.code-profile

Ou seja:

xxxxxxxxxx
PROJETO
   ↓
código, dados, notebooks etc.




PROFILE
   ↓
como o VS Code deve se comportar

Isso torna uma migração muito mais limpa.

Importando um Perfil

Se você tiver, por exemplo:

xxxxxxxxxx
Python-Jupyter.code-profile

Faça:

Pela interface do VS Code

  1. Abra o VS Code.
  2. Pressione ⇧⌘P para abrir a Command Palette.
  3. Digite:
xxxxxxxxxx
Profiles: Import Profile
  1. Selecione Profiles: Import Profile.
  2. Escolha o arquivo:
xxxxxxxxxx
Python-Jupyter.code-profile
  1. O VS Code mostrará o conteúdo do Profile — extensões, configurações etc.
  2. Escolha Create a new profile para criar um Profile separado.

Depois ele aparecerá na lista de Profiles.

Pelo menu

Também se pode acessar:

Code → Settings → Profiles

e procurar a opção de Import Profile.

Verificando Perfis já existentes

Você pode conferir as extensões:

No Profile Python & Jupyter, abra:

⇧⌘X

e veja se aparecem:

xxxxxxxxxx
Python
Pylance
Python Debugger
Jupyter

O .code-profile pode incluir a lista de extensões, mas as extensões precisam ser instaladas na nova máquina; o importador cuida desse processo conforme o conteúdo do Profile.

No caso de uma migração Mac → Ubuntu, se faria:

xxxxxxxxxx
Mac
 │
 ├── Python-Jupyter.code-profile ──────┐
 ├── Markdown-Docs.code-profile        │
 └── ESP32-Arduino.code-profile        │
                                       ↓
                                    Ubuntu
                                       │
                                importar Profiles

e, separadamente, se migraria os environments Conda com os arquivos .yml. Assim você reproduz praticamente todo o seu ambiente de desenvolvimento sem carregar lixo ou configurações específicas do macOS.
